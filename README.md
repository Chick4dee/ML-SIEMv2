# ML-SIEM v2

SIEM/SOAR с ML-детекцией сетевых атак. Разработка идёт вертикальными срезами по
спецификациям в `specs/`; журнал решений — `docs/JOURNAL.md`.

## Быстрый старт

```
uv sync --extra dev
uv run pytest
uv run mlsiem data flows --dataset ctu13 --capture 7
```

Подробнее о пайплайне данных — `specs/001-nids-data-pipeline/quickstart.md`.

## Детекция, инциденты и API (фича 002)

Сквозная цепочка поверх данных фичи 001: детектор → алерты → инциденты → предложения
плейбуков → API аналитика. Реагирование только симулируется — никаких реальных сетевых действий.

```
uv run mlsiem detect train                              # эксперимент logreg vs lgbm, выбор детектора
uv run dvc repro train_detector                         # то же как стадия DVC
uv run mlsiem soc run --split unsw_time --part test     # прогон test через цепочку (--limit N — первые N потоков)
uv run mlsiem soc run --pcap FILE.pcap                  # новый неразмеченный PCAP тем же путём
uv run mlsiem soc status                                # какие прогоны лежат в хранилище
uv run mlsiem soc serve                                 # консоль http://127.0.0.1:8000/ и API /api/v1
```

Где что лежит:

- `models/detector/` — артефакт детектора (`model.joblib`, `model_card.json`, `experiment.json`),
  выход DVC; отчёт эксперимента — `reports/detector_experiment.md`;
- `var/soc.db` — SQLite с прогонами, алертами, инцидентами, действиями и аудит-журналом;
  `var/runs/<run_id>/` — вердикты всех потоков прогона (и `flows.parquet` для PCAP).
  `var/` — рабочее состояние аналитика, ни в git, ни в DVC;
- MLflow: метаданные в `mlflow.db`, файлы runs в `mlruns/` (оба вне git).
  Посмотреть: `uv run mlflow ui --backend-store-uri sqlite:///mlflow.db`;
- документация API (Swagger) — `http://127.0.0.1:8000/docs` при запущенном `soc serve`.
  Изменяющие запросы требуют заголовок `X-Analyst: <имя латиницей>`.

Конфиги — `configs/detect.yaml` (кандидаты, правило выбора, сид) и `configs/soc.yaml`
(окно группировки, серьёзность, защищённые адреса, правила плейбуков). Сценарии проверки —
`specs/002-detection-incident-chain/quickstart.md`.

## Консоль аналитика SOC (фича 003)

Веб-консоль поверх цепочки 002: панель прогона, список инцидентов с фильтрами и сортировкой,
карточка (алерты, вероятности детектора, гистограмма, хронология, аудит), решения аналитика
и журнал аудита. Серверные страницы на Jinja2 + htmx 2 (файл лежит в пакете, без сборки
и CDN) — консоль работает без интернета, основные страницы читаются и без JavaScript.

```
uv run mlsiem soc serve        # консоль http://127.0.0.1:8000/, API http://127.0.0.1:8000/api/v1
```

- **Одна команда, один порт**: консоль и API 002 в одном процессе; слушает только 127.0.0.1.
  При первом запуске база 002 автоматически переводится на схему 2 (поле «ответственный»,
  новое событие аудита) — одной транзакцией, все записи аудита сохраняются как есть.
- **Представиться**: кнопка «представиться» в шапке — имя (можно кириллицей) запоминается
  в браузере и подписывает каждое решение в журнале. Пароля нет: это подпись, а не вход.
- **Решения** идут через те же правила, что API 002: допустимые переходы статусов, резолюция
  при закрытии, подтверждение действия после явного вопроса (выполнение только симулируется),
  защита от одновременных правок. Если решает не ответственный — консоль предупреждает,
  а аудит отмечает `by_non_assignee`.
- **Метки «подозрительный источник»** — подсказка, а не решение: источник из сети жертв или
  фона (`networks` в `configs/soc.yaml`) или адрес, который сам бывает целью в других
  инцидентах прогона (признак ответного направления). Серьёзность и действие метка не меняет;
  есть фильтр «только/скрыть подозрительные».
- **Живое обновление**: панель, список и баннер «появился новый прогон» опрашивают сервер раз
  в `ui.refresh_seconds` (10 с) и не трогают формы; при недоступности сервера появляется
  полоса «данные могут быть устаревшими».
- **Защита**: изменяющие запросы консоли принимаются только со страниц самой консоли
  (проверка `Origin`/`Sec-Fetch-Site` + подписанный токен формы), чужие — 403 и запись
  в лог; строгая CSP без inline-скриптов; все данные выводятся экранированными.

Настройки — разделы `networks` и `ui` в `configs/soc.yaml`. htmx: версия и SHA-256 —
`src/mlsiem/ui/static/vendor/README.md`. Сценарии проверки —
`specs/003-soc-console-ui/quickstart.md`.
