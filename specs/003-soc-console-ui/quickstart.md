# Quickstart: SOC-консоль аналитика (003)

Сценарии, которыми проверяется, что фича работает целиком. Детали адресов и форм —
[contracts/ui.md](contracts/ui.md), дополнения API — [contracts/api-v1-additions.md](contracts/api-v1-additions.md),
сущности — [data-model.md](data-model.md).

## Предварительно

- Готова фича 002: есть `models/detector/` и хотя бы один прогон в `var/soc.db`. Если базы нет:

```bash
uv run mlsiem soc run --split unsw_time --part test
```

- Зависимости обновлены (`python-multipart`, dev — `beautifulsoup4`):

```bash
uv sync --extra dev
```

## 1. Автоматические тесты

```bash
uv run pytest
```

Ожидаемо: все быстрые тесты зелёные, включая `tests/ui/` (страницы, фрагменты, решения,
CSRF, экранирование, работа без JS, метки, счётчики панели) и тест миграции базы 002 → схема 2.

```bash
uv run pytest -m slow -k ui
```

Ожидаемо: на реальном прогоне 002 метку сети жертв/фона получают все инциденты с источниками
из этих сетей — 14 из 66 (8 с 149.171.126.x и 6 с 59.166.0.x; «17» в журнале 002 оказалось
ошибкой подсчёта), SC-003; панель, список и карточка самого большого инцидента отвечают
быстрее 1 с (SC-001).

## 2. Запуск консоли

```bash
uv run mlsiem soc serve
```

Ожидаемо: в логе адреса консоли `http://127.0.0.1:8000/` и API `http://127.0.0.1:8000/api/v1`;
старая база автоматически мигрирована (сообщение «схема базы обновлена до версии 2», аудит
сохранён). Интернет не нужен (SC-008): в DevTools → Network нет запросов на внешние адреса.

## 3. Сценарий аналитика (US1 + US2, SC-002)

1. Открыть `http://127.0.0.1:8000/` → панель последнего прогона: счётчики по статусу,
   серьёзности, классам, «ждут решения», «без ответственного», «подозрительный источник»,
   последние алерты.
2. Нажать «представиться», ввести имя (например, `Влад`) → имя в шапке.
3. Кликнуть по счётчику «critical» → список с фильтром `severity=critical`; число строк равно
   счётчику (SC-004). Добавить фильтр по классу и отсортировать по числу алертов — адрес
   страницы меняется, страница не перезагружается. Скопировать адрес, открыть в новой
   вкладке — тот же вид.
4. Открыть верхний инцидент: ключ, цели, серьёзность с объяснением, предложенное действие
   с правилом, гистограмма алертов, хронология, история, аудит. Раскрыть алерт —
   вероятности по классам и порог.
5. «Взять себе» → ответственный = ваше имя, в хронологии и истории новая запись.
6. «В работу» → статус меняется без перезагрузки.
7. «Подтвердить действие» → вопрос с действием и объектом → подтвердить → блок симуляции
   и надпись «реальных изменений не было».
8. «Закрыть» без резолюции — форма не отправляется; с резолюцией «подтверждён» и комментарием
   — закрыт, кнопки статуса пропали.

## 4. Конфликт и чужой ответственный (US2 сц. 7, 9)

1. Открыть один инцидент в двух окнах; во втором окне сменить имя на `alice` (`/analyst`).
2. В первом окне назначить инцидент на себя. Во втором окне через ≤ 10 с появится полоса
   «инцидент изменён — обновить», введённый комментарий не пропал.
3. Во втором окне (не обновляя) нажать «в работу» → сообщение о конфликте и актуальное
   состояние. Обновить и повторить → предупреждение «ответственный — Влад, продолжить?» →
   продолжить → в аудите решения `by_non_assignee: true`.

## 5. Подозрительные источники (US3)

1. На панели кликнуть «подозрительный источник» → список помеченных инцидентов; у каждого
   метка «жертвы UNSW-NB15», «фон UNSW-NB15» или «источник — цель в других инцидентах».
2. Открыть такой инцидент → объяснение метки и ссылки на связанные инциденты; закрыть как
   «ложное срабатывание» обычным путём.
3. Фильтр «скрыть подозрительные» → остальные инциденты; серьёзность и действия у помеченных
   не изменились.

## 6. Живое обновление и новый прогон (US4)

1. Держать панель открытой. В терминале:

```bash
uv run mlsiem soc run --split unsw_time --part test --limit 50000
```

2. Ожидаемо: через ≤ 15 с баннер «появился новый прогон … — переключиться»; прогон на экране
   сам не сменился (SC-006, FR-023).
3. Остановить сервер (Ctrl+C) → на странице полоса «данные могут быть устаревшими»; запустить
   снова → полоса пропала.

## 7. Журнал аудита (US5)

Открыть `/audit`, отфильтровать по своему имени и событию «действие подтверждено» → ваши
решения, новые сверху, с переходом к инциденту. Кнопок изменения и удаления нет.

## 8. Безопасность (FR-029, FR-029a, SC-009)

1. Представиться именем `<script>alert(1)</script>` и оставить такой же комментарий →
   текст виден как есть, окно не всплывает.
2. Попытка межсайтового запроса (ожидаемо `403`, база не изменилась, предупреждение в логе
   сервера):

```bash
curl -i -X POST http://127.0.0.1:8000/incidents/<incident_id>/status -H "Origin: http://evil.example" -H "Sec-Fetch-Site: cross-site" -d "status=in_progress&expected_version=1"
```

## 9. Без JavaScript (FR-032)

Отключить JavaScript в DevTools, открыть `/`, `/incidents` (применить фильтр кнопкой
«показать»), карточку и `/audit` — всё читается, фильтры и пагинация работают.
