# Контракт: веб-консоль аналитика

Базовый адрес: `http://127.0.0.1:8000/` (тот же процесс и порт, что API 002, команда
`mlsiem soc serve`). Ответы — HTML в UTF-8. Все страницы и фрагменты:

- отдают полную страницу на обычный запрос и **только фрагмент**, если есть заголовок
  `HX-Request: true` без `HX-Boosted` (research R2);
- имеют заголовки `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'`,
  `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`;
- экранируют все данные (autoescape Jinja2 включён для `.html`) — FR-029.

## Страницы (GET)

| Адрес | Что показывает | Требования |
|---|---|---|
| `/` | обзорная панель выбранного прогона (`?run=`) | US4, FR-021–023 |
| `/incidents` | список инцидентов; параметры — `IncidentListView` из data-model | US1, US3, FR-004–008 |
| `/incidents/{incident_id}` | карточка инцидента | US1, US2, FR-009–017 |
| `/audit` | журнал аудита: `?actor=&event=&incident=&run=&page=` | US5, FR-026–027 |
| `/analyst` | форма «представиться / сменить имя» (`?next=` — куда вернуться) | FR-002 |

Пустая база → на `/` и `/incidents` объяснение и команда `uv run mlsiem soc run …`
вместо таблиц. Неизвестный инцидент → `404` со страницей «не найдено» и ссылкой на список.

## Фрагменты (GET, для htmx; без `HX-Request` отдают полную страницу-обёртку)

| Адрес | Назначение | Опрос |
|---|---|---|
| `/incidents?…` c `HX-Request` | таблица списка + счётчик найденных + пагинация | да, с `If-None-Match` → `204` без изменений |
| `/fragments/dashboard?run=` | счётчики панели | да |
| `/fragments/recent-alerts?run=` | лента последних алертов | да |
| `/fragments/runs-banner?run=` | баннер «появился новый прогон X — переключиться» (пусто, если нового нет) | да |
| `/fragments/incidents/{id}/stamp` | `version` инцидента и действия; при расхождении с `?v=&av=` — полоса «инцидент изменён — обновить» | да |
| `/fragments/incidents/{id}/alerts?page=` | страница алертов карточки | нет |
| `/fragments/alerts/{run_id}/{flow_uid}/probs` | вероятности по классам и порог (раскрытие алерта) | нет |
| `/fragments/incidents/{id}/timeline` | хронология событий | нет (обновляется после решения) |

Опрос: `hx-trigger="every {refresh_seconds}s"`. Ошибка опроса → в интерфейсе полоса «данные
могут быть устаревшими», первый успешный ответ её снимает.

## Изменяющие запросы (POST)

Общее для всех:

- Тело — `application/x-www-form-urlencoded`, поле `csrf_token` **или** заголовок
  `X-CSRF-Token`; проверка источника и токена — research R7. Отказ → `403` + фрагмент
  «запрос отклонён: он пришёл не со страницы консоли» (или «страница устарела — обновите
  её» для просроченного токена), в базе без изменений, запись в лог `mlsiem.ui.security`.
- Автор — cookie `mlsiem_analyst`; нет → `401` + фрагмент «представьтесь» со ссылкой на
  `/analyst?next=…`, введённые поля возвращаются в форму.
- `expected_version` — скрытое поле из отрисованной карточки.
- Ответ htmx — обновлённые фрагменты карточки (панель действия/статуса + `HX-Trigger:
  incident-changed` для перерисовки хронологии и истории). Без htmx — `303` на карточку.
- Ошибки `store` → статус как в API 002 (`404/409/400`) и фрагмент ошибки рядом с формой
  с русским `message`, введённые поля (комментарий, резолюция) сохраняются. Для `conflict` —
  дополнительно актуальное состояние инцидента и кнопка «повторить на новой версии».

| Адрес | Поля формы | Store | Требования |
|---|---|---|---|
| `POST /analyst` | `name`, `next` | — (ставит cookie) | FR-002 |
| `POST /incidents/{id}/assign` | `assignee` (пусто = снять), `take=1` («взять себе» = текущее имя), `comment`, `expected_version` | `store.assign` | FR-012 |
| `POST /incidents/{id}/status` | `status`, `resolution`, `comment`, `expected_version`, `ack_not_assignee` | `store.change_status` | FR-012a, FR-013 |
| `POST /actions/{action_id}/confirm` | `comment`, `expected_version`, `ack_not_assignee`, `ack_action=1` | `store.confirm_action` | FR-012a, FR-014, FR-015 |
| `POST /actions/{action_id}/reject` | `comment` (обязателен), `expected_version`, `ack_not_assignee` | `store.reject_action` | FR-012a, FR-014 |

Правила консоли поверх `store`:

- **Подтверждение действия** требует `ack_action=1`: без него сервер возвращает фрагмент-вопрос
  «Подтвердить: <действие> для <объект>? Выполнение только симулируется» с кнопкой, которая
  отправляет ту же форму с флагом. С JS это `<dialog>`; без JS — промежуточная страница.
- **Не ответственный** (ответственный задан и ≠ текущему имени): без `ack_not_assignee=1`
  сервер возвращает фрагмент-предупреждение «Ответственный — X. Всё равно продолжить?»
  и решение не применяет (research R6).
- **Закрытие** без `resolution` и **отклонение** без `comment` отсекаются ещё в форме
  (`required`), а сервер дублирует проверку через `store` (`400`).
- Кнопки выводятся только для допустимых переходов: у `closed` нет смены статуса; у действия
  не в `proposed` нет кнопок решения.
- После подтверждения показывается блок симуляции: тип, объект, описание из
  `action.simulation` и фраза «Реальных изменений в сети и на хостах не было».

## Параметры по адресу страницы

`/incidents` принимает параметры `IncidentListView` (data-model). Некорректное значение
игнорируется с предупреждением над таблицей. Кнопка «сбросить фильтры» ведёт на
`/incidents?run=<текущий>`. Ссылки счётчиков панели — ровно те фильтры, что дают это число.

## Статика

`/static/console.css`, `/static/console.js`, `/static/vendor/htmx.min.js` (версия и SHA-256 —
в `static/vendor/README.md`, сверяются тестом). Внешних адресов в страницах нет.
