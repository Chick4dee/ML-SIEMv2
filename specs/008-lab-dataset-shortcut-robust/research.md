# Research: Содержательный набор стенда, устойчивый к «ярлыкам»

Решения принимались по умолчанию (спецификация: «развилки решать вариантами по умолчанию»); каждое
записано с альтернативой, чтобы владелец мог вернуться.

## R1. Расширять `mlsiem.lab`, а не заменять

**Решение**: журнал, реестр сценариев, норма и разметка наращиваются необязательными полями и
списками; записи версии 1 (006) читаются как есть, поля версии 2 по умолчанию пустые.
**Почему**: 006 принят и работает вживую; переписывание ломает приёмку.
**Альтернатива**: новый пакет `mlsiem.lab2` — отвергнута (дублирование разметки и канала).

## R2. Источники: вторая ВМ и алиасы

**Решение**: добавить `mlsiem-attacker2` (Debian 12 generic cloud, 512 МБ, `10.88.0.31`) и
`mlsiem-client` (клиент нормы, Ubuntu, 512 МБ, `10.88.0.40`); на `mlsiem-attacker` — алиасы адреса
`.32`, `.33` для последовательных запусков. Реестр источников — `lab.sources` в конфиге (имя, ВМ или
алиас, адрес, роль, ОС, путь управления).
**Почему**: разные образы дают различие стека (окно TCP, таймстемпы, ECN) — это и есть ярлык,
который хочется измерить; одновременные атаки требуют разных машин.
**Альтернативы**: только алиасы на одной ВМ (не меняют стек и не позволяют одновременность);
сетевые пространства имён (сложнее, стек тот же).

## R3. Привязка адреса источника к инструменту

| Инструмент | Способ |
|---|---|
| nmap | `-S <ip> -e <iface>` |
| masscan | `--source-ip <ip>` |
| hping3 | `-a <ip>` (только в изолированной сети, цель в `lab.subnet`) |
| curl, ab | `--interface <ip>` / `-B` |
| hydra, medusa, ffuf, gobuster, slowhttptest, slowloris | `ip route replace <подсеть> dev <iface> src <ip>` перед запуском (последовательные запуски на одной ВМ) |

**Решение**: способ — в конфиге варианта (`source_bind`), раннер подставляет его перед запуском.
Параллельные запуски — только с разных ВМ.
**Почему**: так одновременные атаки не подменяют друг другу маршрут.

## R4. Состав классов, инструментов и вариантов

| Класс (ожидаемый класс UNSW) | Инструмент 1 | Инструмент 2 |
|---|---|---|
| сканирование портов (reconnaissance) | nmap (`-sS`, `-sT`) | masscan |
| веб-фаззинг (fuzzers) | ffuf | gobuster |
| перебор паролей SSH (вне таксономии) | hydra | medusa |
| медленный DoS (dos) | slowhttptest | slowloris |
| затопление с лимитом скорости (dos) | hping3 SYN | hping3 UDP |
| эксплуатация простого уязвимого веб-приложения (exploits) | sqlmap | nikto |
| периодические «маячки» (вне таксономии) | curl-цикл с джиттером | скрипт на python |
| сложная норма (benign) | `ab` (нагрузочный тест) | `nmap -sT` по трём портам с меткой нормы |

**Почему**: по два инструмента на класс нужны для «исключения инструмента» (FR-013); «маячки» —
ближайший аналог класса, который не находят ни публичные датасеты, ни наши модели (Bot).

## R5. Параметры повторов и значения только для теста

**Решение**: у варианта в конфиге — домены параметров (`values`) и подмножество `holdout`; план
распределяет значения случайно по сиду, значения `holdout` попадают только в тестовые повторы.
**Почему**: проверка «новой разновидности» (FR-005) без отдельной ручной работы.

## R6. План и возобновление

**Решение**: `lab plan` создаёт `plan.json` (сид, список запусков с вариантом, параметрами,
источником, номером повтора, частью разбиения, признаком одновременной нормы или второй атаки,
смещением старта); `lab collect` выполняет запуски по порядку, перед каждым проверяет паузу и цели,
пишет журнал; при повторном запуске выполненные `run_uid` пропускаются.
**Паузы**: не меньше idle-таймаута экстрактора плюс запас 30 с (150 с при 120 с). Норма идёт
непрерывно с клиента, а между атаками — и с атакующих хостов.
**Оценка времени**: 140 запусков × (≤ 120 с + 150 с) ≈ 10–11 часов; показывается до старта.

## R7. Разметка по источнику, цели и окну (расширение 006)

**Решение**: `label_flow` принимает список источников записи (`source_ip` записи журнала вместо
единственного адреса атакующего); одновременные запуски с разных источников не пересекаются по
паре (источник, цель). Потоки внутри паузы и на границе окна — `ambiguous`.
**Правило нормы**: на хосте-атакующем норма в окне собственной атаки не запускается (раннер
исключает), в паузах — разрешена; метки `benign` для таких потоков корректны.

## R8. Разбиение по повторам и по времени

**Решение**: повторы 1–6 — обучение, 7–8 — валидация, 9–10 — тест; перед тестом и валидацией —
зазор (пауза плана). Резерв «неизвестное» (классы и варианты) — только в тесте. Для норм —
разбиение по времени сеанса, чтобы норма была и в обучении, и в тесте.

## R9. Отчёт качества и вердикт

**Решение**: таблицы класс × инструмент × источник × часть × интервал времени сеанса; для пар
(класс, инструмент) и (класс, источник) — нормированная взаимная информация (NMI) с порогом из
конфига (по умолчанию 0,9): выше порога — `suspect` с перечнем. Дополнительно — предупреждение,
если класс присутствует только в одной части или одним инструментом.

## R10. Исключение инструмента и хоста

**Решение**: базовая модель — LightGBM как кандидат 002 (`build_candidate`) на потоковых
признаках 001; для каждого (класс, инструмент) обучение без этого инструмента класса, оценка на
нём; для каждого источника — обучение без источника. Порог — квантиль нормы валидации (1%).
Метрика — полнота при заданной доле ложных срабатываний + интервал Уилсона; сравнение с контролем,
где инструмент (источник) присутствует в обучении.
**Альтернатива**: сразу нейросеть 007 — отвергнута: дольше, а вопрос про данные, не про модель.

## R11. Аудит признаков окружения

**Решение**: конфигурируемый список `shortcuts.env_features` (по умолчанию счётчики флагов ECE/CWR/URG
и минимальный/максимальный размер пакета — зависят от стека и инструмента); отчёт: перестановочная
важность, одиночная полнота (как аудит 001/002) и повторная оценка без этих признаков. Вердикт:
`clean`, если качество без них падает меньше порога (по умолчанию 0,05), иначе `suspect`.

## R12. Способы оценки неизвестного в проекте

**Решение**: `mlsiem.detect.openset` — четыре функции по логитам классификатора: атака/норма
(`ln Σ_{c≠b} exp z_c − z_b`), MSP (`1 − max softmax`), энергия (`−ln Σ exp z_c`) и объединение по
p-значениям нормы валидации (`max_i F_i(s_i)`). Логиты берутся из сырых выходов бустинга (не из
вероятностей: они насыщаются, как показали публикации).
**Почему не в 007**: оценка — свойство набора и стенда, а не эксперта окон.

## R13. Память хоста на время сбора

**Решение**: на время сбора потребитель и консоль остановлены; сенсор и брокер работают, поток
не нужен: признаки считаются потом из записи (как в 006). Новые ВМ — по 512 МБ. Проверка запаса —
`stand check` (≥ 4 ГБ, SC-009 006).
**Альтернатива**: уменьшить число источников — запасной вариант, если запас не достигается.

## R14. Граница применимости «нулевого дня»

**Решение**: формулировка «неизвестная атака» применяется к резерву классов и вариантов (FR-021);
в отчёте и README — оговорка FR-023. Слово «нулевой день» без оговорки не используется.

## R15. Безопасная остановка и возобновление (FR-024…FR-029)

**Проблема**: сбор длится 10–11 часов, а владелец не хочет оставлять компьютер на ночь. Оборванный
запуск делает хвост атаки «нормой» и портит набор.

**Решение**:
1. **Запуск — единица атомарности.** Перед запуском в журнал сразу пишется запись `started` (flush), по
   окончании — `completed`; нет конца → `aborted` (потоки окна — `ambiguous`, запуск повторяется целиком с
   новым номером попытки).
2. **Мягкая остановка** (`lab collect stop`, Ctrl+C): доводит текущий запуск, затем дренаж (idle-таймаут +
   30 с), останавливает норму и сенсор, пишет `collect_state.json`. Стоп-флаг — файл рядом с планом: так
   команду можно подать из другого окна.
3. **Срочная остановка** (повторная команда): прерывает запуск, пишет `aborted`; запись сегмента закрывается.
4. **Сеансы**: каждый старт создаёт сеанс с собственными `session.pcap` и `journal.jsonl`; построитель набора
   принимает список сегментов и склеивает по времени сеансов; потоки на границах сеансов — `ambiguous`.
5. **ВМ**: безопасно либо оставить включёнными (хост не спит), либо сохранить (`Save-VM`) и вернуть
   (`Start-VM`); перед возобновлением — проверка часов (`clock_skew_max_s`), при расхождении — синхронизация и
   повторная проверка.
6. **Практика**: сбор разбивается на сеансы по 3–4 часа; последняя команда перед выключением компьютера —
   `lab collect stop`, она печатает «можно выключать» только после дренажа.

**Почему не «просто --resume»**: возобновление пропускает выполненные запуски, но не защищает от обрыва
посреди атаки и от потоков, пересекающих остановку; без атомарности запуска и дренажа норма загрязняется.
**Альтернатива**: приостановка ВМ без остановки сбора — отвергнута: часы и сеансы сенсора расходятся.
