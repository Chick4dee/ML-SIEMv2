# Implementation Plan: Содержательный набор стенда, устойчивый к «ярлыкам»

**Branch**: `008-lab-dataset-shortcut-robust` | **Date**: 2026-10-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-lab-dataset-shortcut-robust/spec.md`

## Summary

Фича расширяет стенд и раннер 006 и добавляет три слоя поверх готового пакета `mlsiem.lab`:
**сбор** (несколько инструментов на класс, несколько источников, повторы с разными параметрами,
сложная норма, планировщик с возобновлением), **качество** (набор версии 2 с метками класса,
варианта, инструмента, источника и запуска; отчёт о связанности классов с инструментом, источником
и временем; вердикт `clean`/`suspect`) и **оценка** (перенос, «исключение инструмента» и «исключение
хоста», аудит признаков, раздел «неизвестные атаки» с оговоркой о границе применимости).

Ничего из 001–007 не переписывается: журнал получает необязательные поля (версия записи 2),
разметка потоков принимает список источников, а новые оценки реализованы отдельными модулями.
Для раздела «неизвестные атаки» (FR-021…FR-023) в `mlsiem.detect` добавляется небольшой модуль
способов оценки неизвестного (атака/норма, MSP, энергия, объединение по p-значениям нормы):
в проекте его нет, а публикации считали это вне основного кода.

Сквозной результат (конституция I): владелец запускает `lab collect` (подтверждает старт) →
по готовности `lab dataset build` → `lab quality` / `lab shortcuts` / `lab unknown` → получает
версионированный набор и отчёт, где перенос и поимка показаны вместе с оценкой при исключённом
инструменте и хосте.

## Technical Context

**Language/Version**: Python 3.11 (пакет `mlsiem`) + PowerShell 5.1 (скрипты Hyper-V) + гостевой
Linux (Ubuntu Server 24.04 и Debian 12 cloud-образ для второго источника).

**Primary Dependencies**:
- уже есть: nfstream (001), polars/numpy/scikit-learn/LightGBM/MLflow, pydantic-модели конфига
  (006 `LabConfig`), каналы COM (006 `lab.channel`);
- **новое на машинах стенда** (из репозиториев ОС, на время установки): masscan, medusa, gobuster,
  slowloris (скрипт), hping3, nikto, sqlmap, apache2-utils (`ab`), маленькое уязвимое веб-приложение
  на жертве (cloud-init), на втором источнике — Debian 12 generic cloud;
- **новых Python-зависимостей на хосте не требуется**.

**Storage**: набор `data/lab/<версия>/` (DVC, как 006) + `plan.json`, `journal.jsonl`,
`quality.json`, `shortcuts.json`, `unknown.json` в каталоге набора; отчёты — `reports/lab_*`;
журнал проекта — `docs/JOURNAL.md`; эксперименты — MLflow `lab`.

**Testing**: pytest; быстрые тесты без ВМ (план, разметка, отчёт качества, оценки на синтетике);
живые проверки — маркер `lab` на поднятом стенде.

**Target Platform**: Windows 11 + Hyper-V (стенд), как 005/006.

**Project Type**: расширение существующего пакета + скрипты стенда.

**Performance Goals**: сбор ~10–12 часов без вмешательства; построение набора и отчётов — минуты.

**Constraints**: изоляция сети стенда не нарушается (FR-005 006); запас памяти хоста ≥ 4 ГБ
(SC-009 006) — на время сбора потребитель и консоль выключены, новые ВМ по 512 МБ; все изменения
на машине владельца — по подтверждению.

**Scale/Scope**: 7 классов × 2 инструмента × 10 повторов ≈ 140 запусков по 90–120 с плюс паузы;
2–3 источника атак, 2 источника нормы; ≥ 20 000 нормальных потоков в тесте.

## Constitution Check

| Принцип | Соответствие |
|---|---|
| I. Вертикальные срезы | Фича заканчивается запускаемым результатом: `lab collect` → набор → отчёт оценки. Инфраструктура (планировщик, отчёты) — внутри фичи, не отдельной фазой. |
| II. Единство признаков | Набор строится тем же экстрактором и схемой 001 (как 006); адреса, порты и время остаются метаданными, в признаки не идут. |
| III. Честная оценка | Порог по валидации, разбиение по времени и повторам, интервалы Уилсона, несколько сидов; аудит артефактов — обязательная часть (FR-015). Непойманное разбирается, а не скрывается. |
| IV. Решения через эксперимент | Все новые оценки сравниваются с бейзлайном (бустинг, A/Н) на тех же сплитах; усложнение (объединение) принимается по цифрам отчёта. |
| V. Безопасный SOAR | Не затрагивается; атаки только в изолированной сети. |
| VI. Воспроизводимость | План по сиду, версия набора, манифест (инструменты, версии, сид, хеш плана); тесты; запись в `docs/JOURNAL.md`. |
| VII. Прозрачное авторство | Без упоминаний ИИ в коде и коммитах. |

Нарушений нет; таблица сложности не требуется.

## Основные риски и порядок снятия

1. **Память хоста.** Свободно было 1,2–1,5 ГБ из 16 на нагрузочных замерах; ещё две ВМ могут
   выйти за запас SC-009 006. Снятие: на время сбора потребитель и консоль выключены (потоки
   нужны только из записи), новые ВМ по 512 МБ, `stand check` проверяет запас до старта.
2. **Привязка источника у инструментов.** Не все инструменты умеют задавать адрес источника.
   Снятие: R3 — таблица способов (флаг инструмента → `ip route … src` для последовательных
   запусков → отдельная ВМ для одновременных).
3. **Новые инструменты в репозиториях ОС.** Часть пакетов может отсутствовать. Снятие: Edge Case
   спецификации; `lab tools check` показывает недоступное до сбора.
4. **Длительность сбора.** Паузы ≥ таймаут простоя + запас складываются в часы. Снятие: паузы
   выдерживаются, но норма идёт непрерывно, а запуски идут с лимитом 90–120 с; оценка времени
   показывается до старта, возобновление после прерывания.
5. **Остановка посреди сбора.** Владелец не оставляет компьютер на ночь. Снятие: R15 — атомарность запуска,
   мягкая и срочная остановка, сеансы с сегментами записи и журнала, дренаж потоков, `collect_state.json`.
6. **Ярлыки не исчезают.** Мера измеряет эффект, не устраняет; вердикт `suspect` — штатный
   результат, а не ошибка.
