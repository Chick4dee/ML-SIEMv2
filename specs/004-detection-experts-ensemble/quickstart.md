# Quickstart: проверка фичи 004

Сценарии, доказывающие, что фича работает сквозным путём. Команды — из корня репозитория,
`uv` в PATH. Контракты — [contracts/](contracts/), поля — [data-model.md](data-model.md).

## 0. Предусловия

- Данные 001 (`data/flows/unsw`, `data/splits/unsw_time.*`) и детектор 002 (`models/detector/`,
  версия `20260924-886cf326`) на месте: `uv run mlsiem soc status` показывает прогоны 002/003.
- Рабочая база `var/soc.db` в схеме 2 (после 003). Перед первым запуском 004 — копия:
  `copy var\soc.db var\soc.db.bak-003`.

## 1. Быстрые тесты

```bash
uv run pytest
```

Ожидание: все тесты 002/003 и новые тесты 004 зелёные; `uv run ruff check .` чистый.

## 2. Эксперимент ансамбля (US1, US2)

```bash
uv run mlsiem detect ensemble
```

Ожидание (≤ 30 мин, ≤ 16 ГБ):
- в stdout — таблица вариантов `classifier`, `any_fired`, `mean_score`, `stack_logreg` с macro
  PR-AUC val/test; у `classifier` — те же 0.711 / 0.697, что в 002 (FR-002);
- у детектора аномалий — оба кандидата, PR-AUC «атака/не атака» на val/test, доля нормы val
  выше порога ≤ 0.5%;
- таблица «скрытый класс» для `exploits` и `dos`: поимка классификатора без класса, детектора
  аномалий и итогового вердикта на val/test;
- строка выбора с условием (`macro_gain`, `unknown_gain` или «ни одно — одиночный эксперт»);
- помеченные аудитом признаки (если есть);
- появились `models/experts/anomaly/`, `models/ensemble/`, `reports/ensemble_experiment.md`.

Повтор (SC-003): второй запуск даёт те же метрики, версии и выбор —
`fc models\ensemble\experiment.json <копия первого>` без различий в метриках.

## 3. Цепочка с ансамблем (US3)

```bash
uv run mlsiem soc run --split unsw_time --part test
```

Ожидание (≤ 15 мин, SC-004): в сводке — модель прогона, алерты по экспертам, число ответных
потоков, инциденты класса `anomaly` (если выбран ансамбль). Повтор на том же входе — те же
вердикты и инциденты (SC-003).

Отказ при битом эксперте (US3 п. 6): временно переименовать `models/experts/anomaly/model.joblib`
→ `soc run` падает до обработки с именем эксперта; вернуть файл.

## 4. Консоль (US3, SC-005, SC-006)

```bash
uv run mlsiem soc serve
```

В браузере `http://127.0.0.1:8000/`:
1. строка о миграции до схемы 3 в консоли сервера; все прогоны 002/003 открываются;
2. новый прогон: панель показывает модель прогона и алерты по экспертам;
3. карточка инцидента → блок «Кто поднял алерты»; детали алерта → блок «Эксперты» с
   объяснением — за 30 секунд ответить «какие эксперты сработали и почему это атака»;
4. фильтр «аномалия (класс неизвестен)» (если такие инциденты есть) → у них предложено
   «требуется ручной разбор» с правилом «класс атаки неизвестен»;
5. старый прогон 002 → детали алерта «прогон сделан до появления ансамбля», без ошибок.

## 5. Разбор ложных инцидентов (US4, SC-007)

Сначала «до/после» на **одном детекторе** 002, чтобы сравнение было честным (Assumptions):

```bash
uv run mlsiem soc run --split unsw_time --part test --model models/detector
uv run mlsiem soc review-sources --run 20260924T110457-1e531f --after <run_id прогона выше>
```

Ожидание: в отчёте все 14 инцидентов прогона 002 с причинами по потокам; после — меньше 14,
ноль «только из-за ответного направления», `lost: []`. Затем тот же разбор для прогона ансамбля
из §3 (дополнительная цифра для журнала).
