# Контракт: командная строка (фича 006)

Запуск из корня: `uv run mlsiem <группа> <команда>`. Коды возврата, stdout/stderr и язык — как
002/005. Команды 001–005, 007 не меняют поведения. Расширяется группа `stand` (машины стенда),
добавляется группа `lab` (сценарии, норма, набор, оценка), расширяется `stream` (сенсор).
Общая опция — `--config configs/stream.yaml`.

## `stand` — машины стенда (US1)

```
mlsiem stand seed-iso --role broker|victim|attacker [--out var/stand/seed-<role>.iso]
mlsiem stand check            # теперь проверяет и машины стенда, если они подняты
```

- `seed-iso --role` — собрать seed-ISO автоустановки для роли (broker — как 005; victim —
  службы R4 и тестовая SSH-учётка; attacker — инструменты R5 и раннер сценариев). Меняет только
  файл.
- `check` — с хоста: всё из 005 (брокер, топики, отсутствие брокера в сети стенда) плюс, если
  машины стенда подняты: их наличие и адреса, доступность служб жертвы с атакующего, изоляция
  (из сети стенда недоступны хост/брокер/служебная/интернет), расхождение часов ≤ `clock_skew_max_s`,
  работоспособность канала управления атакующим (PowerShell Direct / COM). Код `0` — порядок;
  `1` — перечень проблем с подсказками. Машина выключена → понятное сообщение, не зависание.

Создание машин и зеркалирования — PowerShell-скрипты `stand/hyperv/*.ps1` (владелец, от
администратора, каждый меняющий шаг с подтверждением, `-WhatIf` — план). Новое к 005:

| Скрипт | Делает |
|---|---|
| `40-vm-victim.ps1 -Iso <ubuntu.iso> -Seed <seed-victim.iso>` | ВМ жертвы, адаптер в `mlsiem-lab` (Source для зеркала) + установочный Default Switch |
| `50-vm-attacker.ps1 -Iso <ubuntu.iso> -Seed <seed-attacker.iso>` | ВМ атакующего, адаптер в `mlsiem-lab` (Source) + установочный |
| `60-sensor-adapter.ps1` | добавить брокерной ВМ адаптер в `mlsiem-lab` без IP, `-PortMirroring Destination`; жертве/атакующему — `Source`; +1 ГБ RAM брокеру |
| `45-post-install.ps1 -Role victim\|attacker` | отключить установочный адаптер, `mlsiem stand check` |
| `91-remove-lab.ps1` | удалить ВМ стенда и сенсорный адаптер (брокер и сети 005 не трогает) |

Все идемпотентны: повторный запуск — «уже есть». Перед R7a (fallback отдельной ВМ-сенсор)
`60-sensor-adapter.ps1 -Standalone` создаёт отдельную ВМ вместо адаптера на брокере.

## `stream sensor` — живой сенсор (US2)

```
mlsiem stream sensor start [--iface eth1] [--speed realtime]
mlsiem stream sensor status                 # показатели сенсора (R17), == stream status для sensor:live
mlsiem stream sensor stop                    # завершить сеанс (как stream close --session)
```

- `start` — запускается на брокерной (или сенсорной) машине; слушает `--iface` (приёмник
  зеркала, R7), извлекает потоки тем же экстрактором 001 (R8), отправляет в брокер как источник
  `sensor:live`. Перезапуск продолжает тот же сеанс (FR-018 005). В stderr — показатели раз в
  `report_interval_s`. При недоступности брокера — буфер и досылка (R10), потери считаются.
- `stop` — явно завершает сеанс (статус `completed`).
- Отказ (код `1`) до старта: нет интерфейса/зеркала, несовместимая версия схемы признаков.

Хост-обёртки (через PowerShell Direct, FR-010): `stand/hyperv/70-sensor.ps1 start|stop|status`
вызывают эти команды на машине и возвращают вывод на хост.

## `lab` — сценарии, норма, набор, оценка (US3–US5)

```
mlsiem lab scenario list
mlsiem lab scenario run <name> [--version V]        # с хоста → Direct → атакующая машина
mlsiem lab normal start|stop                         # фоновая норма (FR-019)
mlsiem lab demo                                      # готовность → control_replay → остальные → сводка
mlsiem lab report --run <run_uid>                    # отчёт по запуску сценария (FR-016)
mlsiem lab dataset build [--out data/lab/<версия>]   # запись сенсора + журнал → размеченный набор
mlsiem lab evaluate --dataset <версия> --run <run_id>  # оценка модели на наборе (FR-022)
```

- `scenario run` — проверяет, что все цели в `lab`-подсети (FR-013); параллельный запуск
  отклоняется (код `1`, `rejected`). Пишет запись в журнал сценариев (FR-014).
- `demo` — проверка готовности стенда (`stand check`), затем `control_replay`, затем остальные
  сценарии по порядку; печатает сводку «сценарий → обнаружен/нет → инцидент» (US3 п. 6).
- `report` — число потоков сценария у сенсора, доля с алертом, классы, сработавшие эксперты
  (включая эксперт окон 007, если включён), открытые инциденты, задержки до первого алерта и
  инцидента.
- `dataset build` — забирает pcap сеанса и журнал с машин (Copy-VMFile), прогоняет экстрактором
  001, размечает по журналу (benign / класс / `ambiguous`), сохраняет под `data/lab/<версия>/`
  (DVC), пишет отчёт. `dvc repro` этой стадии — только `--single-item` (опыт 007).
- `evaluate` — модель и порог из артефакта прогона как есть; PR-AUC (macro и «атака/нет»),
  поимка по сценариям, FPR и ложные инциденты на норме; для слабых сценариев — разбор R16;
  запись в MLflow (эксперимент `lab`) и `docs/JOURNAL.md`.

## Совместимость

- `soc run`, `stream replay|consume|status|close|compare` (005) работают как раньше.
- Быстрые тесты не требуют ВМ/админа (захват — записанный pcap, брокер — MemoryBroker 005).
  Живые проверки — маркеры `stand`/`lab`, запускаются явно (FR-026).
